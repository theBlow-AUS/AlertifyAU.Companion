---
name: Companion product decisions
description: User-approved product scope and visual fidelity for the Alertify companion.
---

The Updates screen should combine all feeds in one view, with both near-home/watch-zone and All NSW options, sortable by distance and/or latest update.

**Why:** The user explicitly requested a combined feed rather than only separate source lists.

**How to apply:** Keep individual-source browsing available, use named watch zones for proximity, and never present unlocated or statewide warnings as verified nearby reports.

Let users choose which hazards provide alerts in the app/on device, covering all current hazard feeds. Keep source browsing available independently of alert selection.

**Why:** The user requested hazard alert controls and chose “All current hazard feeds”.

**How to apply:** Preserve individual source opt-outs and the separate opt-in for phone notifications. Do not silently expand existing users' notification subscriptions when adding sources.

The user named the native app **Alertify.au Companion** and explicitly said to keep the approved Alertify branding and visuals as is.

**Why:** The user said “Love it - build it” after approving the canvas concepts. Graduation should preserve the design rather than introduce another visual direction.

**How to apply:** Use the approved Home Watch, incident-detail and trip-handoff concepts as the design reference for future app work.

The audience is people monitoring home first, followed by travellers. Alertify hands navigation off to specialist apps rather than becoming its own navigator. Remembering the chosen navigation app is opt-in. Home and trip alert sensitivity must stay independent.

**Why:** These were explicit decisions made by the user during product exploration.

**How to apply:** Keep the main app home-focused, offer Google Maps/Waze handoff, and never save a navigation preference without the user choosing to remember it.

Support multiple named watch addresses. Match fire danger to the selected address pin using Alertify's district boundaries; do not require manual district selection. Fire danger ratings must display inside the app; the user does not want to go external for them. Use Alertify for TfNSW Live Hazards, BOM NSW Warnings and NSW SES HazardWatch where possible.

**Why:** The user explicitly requested these capabilities and rejected the external-link-only fire danger experience.

**How to apply:** Keep fire rating values and district context in-app rather than replacing them with an external link. Prefer Alertify's existing public feed connections and expose upstream outages honestly.

The user also requested Xweather Lightning, Live Weather Radar, Xweather Hail Threats, Xweather Wind and Xweather Rain for watch zones and trip routing.

**Why:** The user asked to add these sources to the zone/trip experience, not just as a separate generic feed list.

**How to apply:** Keep them relevant to the selected saved zone or estimated trip, while preserving specialist-app navigation handoff and clearly stating sampling/coverage limits.
